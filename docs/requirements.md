## 0. 第一原則：簡單

重做的理由就是「**原本那版設計太複雜**」（Eason 2026-08-01）。
因此本專案的第一原則是簡單好操作：**任何會增加現場操作步驟或欄位的設計，預設不做**，
要加就必須說得出「不加會漏掉什麼」。這條有否決權，凌駕其他功能考量。

## 1. 這是什麼、為什麼要做

現場每天都會發生食材與物料耗損（報廢、過期、備料失誤等）。目前沒有一份**現場自己打、當下就知道賠了多少錢**的紀錄；
月底回頭盤耗損只能靠記憶與零散紙條，既算不出金額，也看不出「哪一類、哪一項在漏錢」。

本專案要做一支**手機開網址就能打**的耗損登記表：現場只記「什麼東西、耗了多少、為什麼」，
金額由系統依成本表自動算，並自動累積成可分析的報表。

### 1.1 與現有 `~/mala-waste` 的關係

`~/mala-waste`（墨竹亭光復店「每日耗損表」v2，2026-07-31 完成）是同一家店的既有系統。
Eason 表示原版設計太複雜，因此重做本支。

**本專案一律不動舊系統**（不改它的程式、不動它的試算表、不動它的 Netlify 站台）。
新的上線後舊的是否退場，由 Eason 屆時決定。兩支若同時存在，**名稱與外觀必須一眼可分**：

- 舊：「每日耗損表」
- 新：「**墨竹亭 光復店 耗損登記表**」

## 2. 使用者

| 角色 | 是誰 | 做什麼 |
|---|---|---|
| 現場登記者 | 光復店門市同仁，1–3 人共用一台手機／平板 | 發生耗損時逐筆登記 |
| 成本維護者 | 主要是 Eason，現場主管也可 | 在 app 的「成本設定」分頁維護品名／品類／單位／單位成本 |
| 看報表的人 | Eason | 看期間總金額、排行與走勢，匯出或列印 |

- **不做帳號密碼**（單店、內部使用）。
- 成本設定分頁**現場也能改**，不加管理密碼。

## 3. 核心功能

### 3.1 登記（第一分頁）

逐筆新增，隨時發生隨時打。**現場只需要動三個地方：品名、耗損量、原因。**

| 欄位 | 誰填 | 說明 |
|---|---|---|
| 品名 | 打字（有記憶提示） | 選中提示 → 品類、單位、單位成本一次帶回 |
| 品類 | 自動帶入，可改 | 來自成本表 |
| **耗損量** | **現場手打（唯一要打的數字）** | 就是實際耗損量，可小數（`1.5` ＝ 一包半） |
| 單位 | 自動帶入，**登記頁不可改** | 來自成本表（包／公斤／盒…） |
| 單位成本 | 自動帶入，**登記頁不可改** | 來自成本表 |
| 金額 | 系統算 | **金額 ＝ 耗損量 × 單位成本**（Eason 定案） |
| 原因 | 下拉固定選項 | 見 3.4 |
| 日期 | 預設今天，可改 | 補登昨天用 |
| 備註 | 選填 | |

> 「數量」與「單位量」**合併成單一數字欄「耗損量」**（Eason 定案：現場只打一個數字最簡單）。
> 單位不逐筆手打，跟著品名走；同一品項要換單位＝去成本設定改，或另建一筆品項。

### 3.2 品項記憶（自動代入）

- 打過的品名會被記住，打前幾個字就出現提示。
- 選中提示 → **品類、單位、單位成本一次帶回**，現場只剩耗損量要打。
- 打了成本表裡沒有的新品名 → 當場可補建（填品類、單位、單位成本），存進成本表後同樣被記住。

### 3.3 成本設定（第二分頁）

- 一份清單：品名、品類、單位、單位成本，可新增／修改／停用／搜尋。
- 這裡是**單位成本的唯一來源**，登記頁一律查這裡。
- **全新開始，不從舊系統帶任何品項與價格**（Eason 定案）。
- **歷史金額永不重算**：每筆耗損存下當下的單位成本與算好的金額；今天改單價不會動到上個月的報表。

### 3.4 耗損原因（固定下拉，已定案）

報廢／過期／備料失誤／客訴重做／試菜／盤點差異／其他（選「其他」要自填說明）。

### 3.5 統計與分析（第三分頁）

- 選期間：本日／本週／本月／自訂區間。
- **期間總金額**大字顯示，附「本期 vs 上期」增減。
- 三張排行：**按品類**、**按品名**、**按原因**（金額、佔比、筆數）。
- **每日走勢**（看得出哪幾天特別高）。
- 匯出 CSV、可列印。

## 4. 形式與資料存放

- **單一 HTML 網頁 app**，手機開網址就能用。
- 資料存 **Google 試算表**（透過 Apps Script 後台），可備份、多台裝置看同一份。
- 「另一個分頁」指的是**網頁 app 裡的分頁**（登記／成本設定／統計），不是試算表分頁。
- 送出失敗要能暫存重送，且**不可產生重複紀錄**。

## 5. 品類（已定案）

肉類／海鮮／蔬菜／豆製品・加工品／乾貨・南北貨／調味料／飲品・酒水／包材・耗材／其他

## 6. 明確不做（第一版範圍外）

- 不做多店（資料結構保留店別欄位，日後改常數即可開放）。
- 不做帳號密碼與權限。
- 不與庫存 app、日報表、POS 串接。
- 不做庫存扣帳（這是耗損紀錄，不是庫存系統）。
- 不做拍照上傳。
- 不改動 `~/mala-waste`。

## 7. 驗收條件（細節在 task.md 逐項展開）

- [ ] 手機新增一筆耗損，全程只需：選品名（有提示）→ 打耗損量 → 選原因 → 送出。

- [ ] 打過一次的品名，第二次能自動帶回品類、單位、單位成本。
- [ ] 統計頁能算出期間總金額，並產出品類／品名／原因三張排行與每日走勢。
- [ ] 送出失敗後重按，資料只會有一筆（不重複）。
- [ ] 與 `~/mala-waste` 名稱、標題色一眼可分。
