                  ▼

**設計取向**：後端只做「存」與「取」，**所有計算與統計都在前端**。
理由是簡單原則——後端一旦開始算錢，就出現第二個計算點，違反第 6 節的約束 1。

## 3. 資料怎麼存（Google 試算表）

一張試算表，三個分頁。**第 1 列為表頭，程式以表頭名稱定位欄位，不寫死欄號。**

### 3.1 分頁 `items`（成本表 ＝ 單位成本的唯一來源）

| 欄 | 名稱 | 型別 | 說明 |
|---|---|---|---|
| A | `品名` | 文字 | **主鍵，唯一**。以名稱為 key，永不改用列號或索引 |
| B | `品類` | 文字 | 限 requirements 第 5 節九選一 |
| C | `單位` | 文字 | 包／公斤／盒／瓶／份… |
| D | `單位成本` | 數字 | 元／單位 |
| E | `停用` | 布林 | `TRUE` 不再出現在提示與下拉 |
| F | `更新時間` | ISO8601 | 例 `2026-08-01T14:30:05+08:00` |

### 3.2 分頁 `loss`（耗損紀錄；**只增不改**）

| 欄 | 名稱 | 型別 | 說明 |
|---|---|---|---|
| A | `id` | 文字 | 去重主鍵，格式見 4.3 |
| B | `日期` | `YYYY-MM-DD` | 耗損發生日（可補登） |
| C | `店別` | 文字 | 固定 `墨竹亭光復`（保留欄位，為日後多店） |
| D | `品類` | 文字 | 送出當下的快照 |
| E | `品名` | 文字 | |
| F | `耗損量` | 數字 | 可小數 |
| G | `單位` | 文字 | **快照** |
| H | `單位成本` | 數字 | **快照**——這是「歷史金額永不重算」的實作核心 |
| I | `金額` | 數字 | **快照**，前端算好才送 |
| J | `原因` | 文字 | 七選一 |
| K | `原因說明` | 文字 | 只有「其他」才有值 |
| L | `備註` | 文字 | |
| M | `建立時間` | ISO8601 | 伺服器時間 |
| N | `作廢` | 布林 | 打錯時用；`TRUE` 的列統計一律排除 |

> **關於打錯怎麼辦**（requirements 沒寫，我自行補上，最小作法）：
> 紀錄只增不改，但登記頁的「今天這幾筆」清單可以按一下作廢。
> 實作是把該列 `作廢` 設為 `TRUE`，**不刪列、不改數字**，統計與 CSV 都排除。
> 沒有這個機制，現場打錯只能將錯就錯，報表就是假的。

> D~I 全部存快照，是刻意的資料冗餘：日後改成本表，這些歷史列不受影響。

### 3.3 分頁 `meta`

`B2` 存一段 JSON 設定（品類清單、原因清單、`rev` 版本號）。
**後端讀寫時必須保留不認得的欄位**（舊專案踩過的坑：後端把 config 重建成固定形狀，前端新加的欄位被靜默吃掉，而本機 mock 測試還全綠）。

## 4. 模組之間怎麼溝通（API 契約）

### 4.1 傳輸方式

- 前端 `fetch(WEB_APP_URL, {method:'POST', headers:{'Content-Type':'text/plain;charset=utf-8'}, body: JSON.stringify(req)})`
  （用 `text/plain` 避開 CORS 預檢，Apps Script Web App 的既有作法。）
- 後端一律回 `200` ＋ JSON：`{"ok": true, "data": ...}` 或 `{"ok": false, "error": "訊息"}`。
- 部署設定：執行身分＝我（Eason）、存取權＝**知道連結的任何人**。

### 4.2 四個 action

| action | 送什麼 | 回什麼 |
|---|---|---|
| `bootstrap` | `{action:"bootstrap"}` | `{items:[...], meta:{...}, serverTime:"..."}`　開頁時抓一次 |
| `saveItem` | `{action:"saveItem", item:{品名,品類,單位,單位成本,停用}}` | `{items:[...]}`　以品名 upsert，回傳整份最新成本表 |
| `addLoss` | `{action:"addLoss", records:[ …見 3.2 A~L… ]}` | `{accepted:[id…], duplicated:[id…]}`　可一次送多筆（補送佇列） |
| `listLoss` | `{action:"listLoss", from:"YYYY-MM-DD", to:"YYYY-MM-DD"}` | `{records:[...]}`　統計頁用 |

### 4.3 `id` 格式（逐字元定義，兩端必須完全一致）

```
格式：  L-<YYYYMMDDHHmmss>-<8 碼隨機小寫英數>
範例：  L-20260801143005-k3f9d2xa
正則：  ^L-\d{14}-[a-z0-9]{8}$
```

- **由前端產生**，在使用者按下「送出」的當下產生一次，之後**永不重產**。
- 後端 `addLoss` 收到已存在的 `id` → 不寫入、放進 `duplicated` 回傳。
- 這是防重複的唯一機制（舊專案的坑：送出失敗→本機先寫→使用者再按一次→變兩筆）。

## 5. 前端模組

| 模組 | 職責 | 純函式？ |
|---|---|---|
| `store` | localStorage 讀寫：成本表快取、待送佇列、草稿 | 否 |
| `api` | 包 fetch、逾時、重試、離線判斷 | 否 |
| **`calc`** | **`makeRecord()`（唯一算金額的地方）**、`summarize()` 統計聚合、`rank()` 排行 | **是（全部）** |
| `ui-log` | 登記頁：品名提示、帶入、送出 | 否 |
| `ui-cost` | 成本設定頁 | 否 |
| `ui-stats` | 統計頁：期間切換、三張排行、走勢、CSV、列印 | 否 |

`calc` 全部寫成不碰 DOM 的純函式，測試才跑得快、金額邏輯才守得住。

### 5.1 金額計算（唯一計算點）

```js
// calc.js —— 全專案唯一一處做乘法的地方
function makeRecord(input, item, nowISO) {
  const qty  = Number(input.耗損量);
  const cost = Number(item.單位成本);
  const 金額 = Math.round(qty * cost * 100) / 100;   // 四捨五入到分
  return { id: input.id, 日期: input.日期, 店別: STORE, 品類: item.品類,
           品名: item.品名, 耗損量: qty, 單位: item.單位, 單位成本: cost,
           金額, 原因: input.原因, 原因說明: input.原因說明 || '',
           備註: input.備註 || '' };
}
```

統計頁**直接加總每筆存下的 `金額`**，一律不得重算。

### 5.2 離線與重送

1. 按送出 → 產 `id` → 寫入 localStorage 待送佇列 → 呼叫 `addLoss`。
2. 成功（在 `accepted` 或 `duplicated` 裡）→ 從佇列移除。
3. 失敗 → 留在佇列，畫面顯示「有 N 筆待上傳」＋一顆「立即重送」。
4. 每次開頁、每次成功送出後，自動試送佇列。

> 舊專案的錯誤示範：提示叫使用者按「立即更新」，但那顆鈕根本不會重送。本專案的重送鈕**必須真的重送佇列**，且要有 e2e 測試蓋住。

## 6. 不可違反的設計約束

1. **金額只在 `makeRecord()` 算一次**，其他任何地方不得自己乘。
2. **歷史金額永不重算**——報表加總 `loss.金額` 欄，不回頭查成本表。
3. **品項一律用名稱當 key**，永不改回列號／陣列索引。
4. **後端讀寫 `meta` 設定必須保留未知欄位**，不得重建成固定形狀。
5. **停用的品項要兩條路都擋**：成本表下拉與打字提示都不能再出現。
6. `dist/index.html` 是產出物，**永不手改**。

| 層 | 工具 | 蓋什麼 |

| 單元 | Node 直接載入 `app.js` 的 `calc` | 金額四捨五入、統計聚合、排行、期間切割、id 格式 |
